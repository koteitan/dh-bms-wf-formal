# BM4 停止性証明 (DH, p.pdf) の Lean 形式化についての検討

作成日: 2026-09-04

## 0. 結論（要約）

- 論文は ZFC の中で BM4 の停止性・整礎性を証明している。Lean 4 + Mathlib は ZFC より強い（無矛盾性の強さで ZFC + 可算個の到達不能基数と同等）ので、**公理の強さが不足して証明できない箇所は無い**。
- ただし、論文の第 III 部（構成可能階層 L、KP、許容順序数、Δ0 論理式、部分真理述語）は Mathlib に**一切存在しない**。ここが形式化コストの大半を占める。第 I・II・V 部（組合せ論と下降法）は Mathlib の既存部品で素直に書ける。
- 公理・推論規則の違いで「証明が通らなくなる」箇所は無いが、**書き方を変えなければならない箇所**が 6 点ある（§3）。最大のものは「KP が証明する」「これは Δ0 である」という散文の主張を、すべて明示的な論理式オブジェクトとその意味論の証明に置き換える必要があること。
- 推奨する構成は、第 IV 部の「安定ラベル」を抽象インターフェース（ラベル系）として切り出し、第 I・II・V 部を第 III 部と独立に完成させること（§4）。
- 今回、定義（配列・親・祖先・展開・主定理の言明）を Lean で書いて型検査を通し、論文の定義 5.1 が yaBMS の BM4 展開と 58 例で一致することを確認した（§7）。

## 1. 論文の構造と Lean への対応

| III (§8–17) | Gödel 符号化、充足コード、L 階層コード、KP、許容性の Σ1 表示、Σ̂q 階層、部分真理述語、Tarski–Vaught、安定関係、有限反映 | ModelTheory（言語・論理式・充足・初等部分構造・Tarski–Vaught・Löwenheim–Skolem・定義可能集合）、ZFSet（ZFC のモデル）、ZFSet 順序数と Ordinal の同型、ω1 の正則性。**L、Δ0、KP、許容順序数は無い** | 非常に高 | 数万行 |

## 3. 公理・推論規則の違いによる問題点（依頼された項目）

### 3.1 強さ: 問題なし

Lean 4 の型理論 + 3 公理（`propext`, `Classical.choice`, `Quot.sound`）は ZFC の全定理を証明できる。論文の全ステップは ZFC 内なので、証明不能になる箇所は無い。完成時の `#print axioms` にこの 3 公理が出るのは正常。

### 3.2 集合の宇宙 V が無い: ZFSet を使う

Lean には「全ての集合の宇宙」は無い。Mathlib の `ZFSet`（Type 1 に住む ZFC のモデル。Lean の宇宙 Type 0 の中の V_κ に相当）を V として使う。論文で V について言うことはすべて ZFSet について言うことになる。

- 推移的集合、∈、Δ0 絶対性は ZFSet の ∈ について文字通り述べられる。
- 順序数は `Ordinal.toZFSetIso` で Mathlib の `Ordinal` と行き来できる。ω1 は `(Ordinal.omega 1).toZFSet`。
- 「BM4 全体は集合である」（§22）や Replacement の使用は、Lean では自明になる。

代替案として L_α を Lean の型として直接作る方法もあるが、Δ0 絶対性と推移性が本質的に集合論的なので推奨しない。

### 3.3 スキーマ vs 項: 外部は問題なし、内部理論は構文が必要

ZFC の Separation/Replacement は論理式スキーマだが、`ZFSet.sep` は任意の Lean 述語 `ZFSet → Prop` を取る（一階式より強いが無害）。

一方、論文が L_θ の**内部**で使う理論 KP は、Lean では実際の一階論理式の集合（`Theory`）として定義しなければならない。つまり論理式が二層になる:

- 外部: Lean の Prop
- 内部: `BoundedFormula` の項（集合論の言語は自作。一つの二項関係記号 ∈ を持つ `Language`）

論文は両者を自然言語で自由に行き来しているが、Lean では移行のたびに「この論理式の Realize はこの Prop と同値」という補題が要る。

### 3.4 「KP が証明する」の扱い: 構文的導出は使わない

§10 の各補題は「KP は … を証明する」という形だが、Lean で形式的証明体系（導出木）を作る必要は無い。代わりに

  「θ が許容順序数（L_θ ⊨ KP）なら、L_θ の中で … が成り立つ」

という意味論的な主張に置き換える。健全性により論文の主張を含意し、必要なのはこの形だけである（系 10.6、補題 11.2、13.3、15.3 はすべてこの形で使われている）。Mathlib の ModelTheory には証明体系が無いので、これが唯一の現実的な道でもある。これは推論規則の違いに見えるが、証明の論理的内容は変わらない。

ただし §10 の証明は「KP 内で Σ1 再帰を回す」という KP の内部推論であり、Lean ではこれを「L_θ ⊨ KP という仮定から、L_θ の元として H, S, D, U が存在することを外部で示す」という形に書き直す。ここが第 III 部で最も手間のかかる部分の一つになる。

### 3.5 「これは Δ0 である」が散文: 各々を明示的な論理式に

§8–15 で「〜は ω をパラメータとする Δ0 関係である」という主張が約 30 箇所ある（SatCode, LCode, FourCode, Seq, Update, BlkUpd, Form, DefInp, KPAx, …）。Lean では各々について

1. Δ0 論理式を `BoundedFormula` の項として実際に書き、
2. その Realize が意図した Prop と同値であることを証明し、
3. Δ0 論理式が推移的集合の間で絶対的であることを一般補題として証明する

必要がある。Mathlib には有界量化 ∀x ∈ y の構文が無いので、Δ0 論理式は「∀x (x ∈ y → φ)」の形を認識する帰納的述語として自作する。これは形式化コストの最大項目である。特に SatCode（定義 8.3）の Tarski 節と LCode（定義 9.1）は長大な論理式になる。

### 3.6 定義的拡大（§12）: Lean には無い

§12 は「原始再帰関数を Δ0 定義可能な関数記号として言語に加えた定義的拡大」を用い、Vars(e), Body(e) を項として書いている。Lean でこれをそのまま行うには、関数記号を加えた言語と保存拡大であることの証明が必要で、負担が大きい。推奨は次のどちらか:

- (a) 関数記号を使わず、常にグラフ（∃v (Graph(e, v) ∧ …)）で書く。論文自身が「最後には消去できる」と述べている通り。
- (b) 符号化を選び直して Vars, Body を Cantor 対の射影にする（Σ̂q 論理式のコードを ⟨ν, d⟩ の対にする）。すると射影は自明に Δ0 になり、§12 の仕組みの大半が不要になる。**こちらを推奨**。

### 3.7 古典論理と選択: 問題なし、ただし定義が noncomputable になる

Lean の核は構成的だが `open Classical` で排中律と選択が使える。補題 6.6、定理 21.1 の背理法はそのまま書ける。

副作用として、親の存在判定を使う `expand` は noncomputable になり `#eval` できない。対策として計算可能版 `expandC` を別に書き、`expand` と一致することを証明する（今回、計算可能版は作成済み。一致証明は未着手）。これは論文の定義 5.1 が本物の BM4 と一致するかを実例で検査するためにも必要（§7）。

### 3.8 その他

- 定理 21.1 は選択公理で安定ラベルの列を作っているが、Lean では不要。「高さ β 以下の安定ラベルを持つ配列からの展開列は停止する」を β についての整礎帰納法（`Ordinal.lt_wf`）で示す方が短い。
- 補題 16.2 の <L-最小証人の選択は `Classical.choice` で置き換えてよい。ω1 の正則性は `Cardinal.isRegular_aleph_one`。
- 補題 16.2 の LΛ ≺ LΘ は Mathlib の下方 Löwenheim–Skolem で可算初等部分構造は得られるが、それが L_Λ の形（順序数の切片）であることは別に示す必要がある。論文通り Skolem 閉包の列の上限を取るか、初等部分構造の鎖の合併が初等であることを使う。
- 定理 17.1 の論理式 Φ は「外部で真である関係」に応じて連言の項を選ぶ。Lean では Classical の `if` で項を選ぶ論理式を定義すればよく、論理的な問題は無い。
- 宇宙レベル: `ZFSet.{0} : Type 1`、`Ordinal.{0} : Type 1`。L_θ の元の型は部分型 `{x // x ∈ Lθ}` で Type 1。ModelTheory は宇宙多相なので問題無い。
- 論文は各 r について証明しているが、Lean では `∀ r` として一括で述べる。行数に関する帰納、親鎖の長さに関する帰納、(C6) の有限反復（備考 6.13）はいずれも通常の帰納法で書ける。命題 6.11 の辞書式順位付けは、各局所補題を必要な仮定を明示した独立の定理として書けば、Lean では自動的に非循環になる（順位を明示する必要は無い）。

## 4. 推奨アーキテクチャ: ラベル系の抽象化

第 IV 部が第 III 部から使うのは次の 4 点だけである。

1. ラベルの型 Ord（許容順序数）と順序 <
2. 各 k ∈ ℕ について関係 ◁_k（補題 15.1: h < k ⇒ ◁_k ⊆ ◁_h、推移的）
3. 有限反映（定理 17.1）: α ◁_n β、有限集合 X ⊆ α、非空有限集合 Y ⊆ [α, β) に対し、Y のパターンを α の下へ写す Y' が存在する
4. 初期対（補題 16.2 / (16.2)）: 全ての k について Λ ◁_k Θ

これを Lean の `structure LabelSystem` として切り出し、第 IV・V 部を `LabelSystem` の任意のインスタンスについて証明する。第 III 部はそのインスタンスを一つ構成する作業になる。利点:

- 第 I・II・IV・V 部（組合せ論と下降法）を先に完成させ、独立に検証できる。
- 第 III 部を後で別の方法（例えば別の順序数割り当て）に差し替えられる。
- 「BM4 の停止性は LabelSystem の存在に帰着する」という中間定理自体が価値を持つ。

## 6. 通読して気づいた点

論文全体を通読した。読んだ範囲で論理的な穴は見つからなかったが、形式化で特に注意を要する箇所と、確認したい点を挙げる。

- 定義 5.1 は任意の（非標準を含む）配列に対して定義されており、公式 BM4 との一致は到達可能配列上でのみ主張される（命題 7.1、備考 7.2）。Lean でも同じ構成にし、公式規則は別途定義して一致を証明する（A5）。
- 補題 4.1 の k > 0 の場合と、補題 6.6 の第 3 段階（「P が有効候補なら P 自身が祖先」とは主張していない旨の注意書き）は、論証が繊細で形式化時に最初に躓きやすい。
- 定理 17.1 の複雑度計算（Σ̂1 を Π̂2 に上げてから Π̂_{n+1} に padding し、外側の ∃ で Σ̂_{n+2}）は、B1 の padding 補題を先に固めておかないと形式化できない。
- 命題 19.1 の場合 (f) は系 6.12 と (17.4) の両方に依存し、k < m0 = n の一致が要となる。ここが第 II 部と第 III 部の接点で、`LabelSystem` の有限反映の言明に (17.4) を含めることが必須。
- 定理 21.1 の証明は選択公理を使っているが不要（§3.8）。論文の修正ではなく Lean 側の簡略化として扱う。
- §12 の定義的拡大は形式化しない（§3.6）。符号化の設計変更を推奨。

- **接頭部分不変性（補題 3.1）は表現の選び方で自明になった。** 配列を `(len, col : ℕ → ℕ → ℕ)` で表し、親・祖先の定義が `len` を読まないようにしたため、一般形「位置 ≤ i で一致する二配列は i の祖先が一致する」（`anc_congr_iff`）だけで済む。

- **命題 7.1 は k < r、i < len に限定して述べた。** 行 k ≥ r の成分は定義上存在するが無意味なので除外する。(7.2), (7.3), 公式規則との一致は r > 0 を仮定する（r = 0 では公式規則の「第 0 成分」が意味を持たない）。
- 論文の定理 17.1 の「(17.2), (17.3) は k < r について」に合わせ、`LabelSystem.reflect` は行数 r を引数に取る。

## 9. Phase B の設計（2026-09-04 決定）

第 III 部は論文の提示をそのまま追うと数万行になるため、次の設計に変更する。定理と証明の骨格（安定ラベル、有限反映、高さ下降）は同じで、内部符号化の範囲を減らす。

### 9.1 論理式は自前の `Fm`（名前付き変数）

Mathlib の `BoundedFormula`（de Bruijn 束縛）は束縛変数の持ち上げで cast が入り、padding・ブロック併合・相対化の構文操作が煩雑になる。`Bm4/SetTheory/Fm.lean` に変数 ℕ の論理式 `Fm` を定義し、充足 `Sat D v φ` を「量化子の範囲 D」を引数に取る形で定義した。`Sat (· ∈ W)` が W への相対化、`Sat (fun _ => True)` が V での充足である。Δ0 絶対性、Σ̂q/Π̂q 階層、双対化、padding、連言の併合（補題 12.2）まで証明済み。

### 9.2 定義可能性は浅い埋め込み `Defin.lean`

「〜は Δ0 である」という主張を、Lean の述語 `P : (ZFSet → Prop) → (ℕ → ZFSet) → Prop`（範囲と付値の述語）に対する `Delta0Def s P` / `SigmaDef q s P` / `PiDef q s P`（s は台となる変数集合）で扱う。閉包補題（∧, ∨, ¬, →, 有界量化、非有界量化、padding）を一度証明すれば、論文の各述語の複雑度は補題の合成で得られる。

### 9.3 初等性は有限族に対して定義する（撤回、9.8 参照）

論文の ◁_k は全ての Σ̂_{k+2} 論理式に対する初等性で、内部で表すには真理述語 Tr_{Σ̂q}（§13）と TV_q（§14）の符号化が必要になる。代わりに、反映に実際に使う有限個の論理式族 F_k（行列部分と双対で閉じたもの）に対する初等性 ElemF F_k で ◁_k を定義する。すると St_k(ξ) は F_k の各 Σ 型論理式 φ についての「∀ā ∈ M (φ(ā) → φ^M(ā))」の有限連言になり、真理述語が不要になる。有限族版の Tarski–Vaught 判定は定理 14.4 と同じ帰納法で示せる。この変更に伴い、ラベル系 `LabelSystem` は行数 r ごとに一つ構成する（`reflect` の r を固定）。

### 9.4 定理 17.1 の論理式を一様にする

論文の Φ は X の元と u_i の個数に応じて連言の個数が変わる。有限族では個数が変わる論理式を全て含められないため、u = (u_0,…,u_{s−1}) を一つの有限列、パターン（どの関係が成り立つか）を有限集合 P として集合パラメータに取る固定論理式 Φ_n にする。Σ1 の証人（L_{u_i} のコード）も一つの列 c にまとめて存在量化する。これで Φ_n ∈ F_n となり、L_α ⊨ Φ_n が反映で得られる。

### 9.5 許容性の内部表現

論文の Adm(η) は KP の公理スキーマの内部真理（KPTrue）を使う。ここでは「良い順序数」good(θ) := ω < θ ∧ θ 極限 ∧ ∀ ξ < θ (L_ξ のコードが L_θ に存在する) を使う。これは L_θ をパラメータとする Δ0 条件なので、内部の Good'(η) は Σ̂1 で書け、good(β) な β で正しく評価される。許容順序数は good である（§10 の Σ1 再帰を Δ0-Collection から直接示す）。反映の議論で必要なのは good だけである。

### 9.6 LCode は論文通り充足コードで内部化する

Def(M)（M 上で定義可能な部分集合）の内部記述には、論理式コードと充足コード SatCode（定義 8.3）が必要である。コードは L_ω（遺伝的有限集合）の中の Kuratowski 対で表し、「コードである」ことは L_ω 内の導出列の有界存在で Δ0 に書く。これは論文 §8–9 に対応する部分で、残りの主要コストである。
